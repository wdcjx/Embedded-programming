# 桌面宠物（四足舵机机器人）SPL 实战 — desktop-pet-spl.md

> 来源：Sngels_wyh 桌面宠物（oshwhub.com/sngelswyh/stm32-smart-desktop-pet，开源）。
> 两个版本实测：**A=2025.2.17 版**（用户指定主体）、**B=2026.3.23 适配国产芯片版**（同工程演进）。
> 芯片 STM32F103C8T6 / Keil SPL / 上板实测运行。本仓库文件级读码沉淀，含 A→B 官方整改对照。

## 1. 工程概览与两版演进

| 维度 | A（2月17日） | B（3月23日） |
|---|---|---|
| 命令处理 | 双串口 ISR 各一份 ~190 行 if-else 复制 | 统一 `PetAction_Judgmengt(Serial_type)`（0=语音/1=蓝牙），ISR 只存 RxData+调它 |
| 表情刷屏 | **USART ISR 里直接调 Face_Config→OLED 全屏刷（软 I2C，几十 ms 级）** | ISR 只置变量，主循环 `Face_Config()` 刷（官方整改示范） |
| 摇尾巴 | 静态姿势后 if(WeiBa) 跳模式 9，重复 3 次退出 | 并发态：`WeiBa_Bit/WeiBa_Value/WeiBa_Dir` 三变量，可打断、记位置续扫 |
| 全局变量 | 散落各 .c | 集中 Variable.c/h（仍未 volatile） |
| 电量 | 无 | ADC PA4 分压、100 次平均、OLED 叠加显示、充电判定 |
| 新命令 | 0x29~0x49 | +0x50 电量显示开关 |
| 模块 | Face_Config 含 ISR 刷屏 | +AD/PowerDetection/Led_Breathing/Timer/Voice 拆模块 |

**B 版"适配国产芯片"实证**：两版 uvprojx 逐项 diff 完全一致（STM32F103C8 / USE_STDPERIPH_DRIVER / startup_stm32f10x_md.s 家族），所谓适配=同代码同 hex 直接烧 CH32F103 类引脚兼容芯片（另有独立发布的"适配国产芯片的HEX固件"）。**国产 F103 兼容芯最省事的路：工程零改动，编译产物直接烧**。

要点：语音与蓝牙**共用同一命令表**，区分仅在 `Sustainedmove`：语音(0)每命令做 2 个循环自动停，蓝牙(1)持续运动直到收到新命令（手机按住=持续走）。手机端=蓝牙串口 App 按键直发单字节 hex，无帧头帧尾——**单字节协议天然无粘包问题**，是最简单的遥控方案。

## 4. 四足步态与动作系统

```
舵机布局（俯视，头朝上）: 1(左上) 2(右上)
                          3(左下) 4(右下)
角度语义: 0=腿向前甩, 90=站立支撑, 180=向后甩
镜像安装: 右侧舵机反装, Servo_Angle2/4 用 (180-Angle) 取反
脉宽换算: CCR = Angle/180*2000 + 500  (0.5~2.5ms @50Hz)
```

- **对角步态（trot）**：前进=先 2+3（右前+左后）摆 45°，再 1+4 摆 135°，回中，交替——四拍循环 `45/135/90/90` 两组；后退同序列反向；左/右转=同侧前后腿同向摆（PAnumbers×2 双倍循环）。
- **可打断设计**：动作函数内每个 `Delay_ms(SpeedDelay)` 后都查 `if(Action_Mode!=N)break;`——ISR 收新命令改 Action_Mode，动作在下一个延时点退出。**动作打断粒度=SpeedDelay（200ms 档可感知延迟，提速档 120ms）**。
- **跳**：TiaoTurn 交替先左对/右对蹬地（140/35），模拟蓄力-蹬伸，落地回站立。
- **伸懒腰**：前腿 90→10 缓慢下压再回，后腿 90→170 上抬再回（15ms 步进=缓动速度）。
- 步态速度两档全局：SpeedDelay（移动 200~120ms）、SwingDelay（摇摆/尾巴 9~4ms），命令 0x38/39 循环调节，到顶回默认（表情反馈：到极限换"狂热脸"）。

## 5. 表情与显示

7 种 128×64 全屏表情图（睡觉/瞪眼/快乐/狂热/非常快乐/眼睛/打招呼）+ 电量叠加（左上角 `Power:xx`，≥110 显示 Charging）。A 版表情在串口 ISR 里刷（见坑 68）；B 版主循环每圈刷——**注意 B 版是每圈无条件全屏重画**（Clear+ShowImage+Update，软 I2C 全屏 ~几十 ms），只因主循环任务是阻塞动作无感知；省电做法=Face_Mode 变化才刷+电量区局部刷。

## 6. 呼吸灯（20ms 时基复用）

TIM3 同时输出尾巴舵机 PWM 与 LED PWM（同一 50Hz 周期）。呼吸灯三段状态机跑在 TIM3 20ms 中断里：HuXi 每 20ms 步进 ±100（0→20000 升 200 步=4s，降 4s，停 20 步=0.4s，全周期 ~8.4s）。LED 亮度=CCR 直接赋值（20ms 周期占空比）。**同一定时器不同通道各干各的，CCR 互不影响——定时器复用的标准用法**。

## 7. 电量检测（B 版）

`(3.3*4*ADC/4096)*100-300`：×4 分压还原电压→百分数化（3.00V 起 0，3.30V=100，量程外≥110 判充电中）。TIM3 20ms 中断里 GetCur_Power 累计 100 次（2s 窗口）平均一次。ADC 为软件触发阻塞单次（江协范式）。

## 8. bug 清单（实测确认）

1. **case 0x39 无 break 贯穿到 0x40**（B_PetAction.c:597-605 与 690-698 两份同款）：调摇摆提速会顺带翻转尾巴开关+改表情。0x38 有 break、0x39 没有——复制漏改，且统一函数后仍是复制粘贴的两份命令表（语音/蓝牙各一份）贯穿错误也复制了两份。坑 47 家族第三例。
2. A 版串口 ISR 刷 OLED（坑 68 主体）；B 版修正但引入每圈全屏重画（性能糙点）。
3. `Time`/`temp` 等变量声明未用（死变量）；A 版 `Sustainedmove` 语音通道置 0 后 walk 动作循环条件 `(PAnumbers||Sustainedmove)` 靠 PAnumbers 兜底，逻辑能走但语义混乱。
4. B 版 RxData_Voice/RxData_Blue 为 Variable.c 定义的非 volatile 全局，ISR 写+主循环读（真实隐患，validator 单文件盲区）。
5. 电量公式把 3.0~3.3V 映射 0~100%，3.3~4.2V 满电区间显示溢出值（≥110 判充电是补救而非设计）——公式粗糙但可用。

## 9. validator 记录

A_BlueTooth.c=16 VIOLATION（双 ISR 访 8 个非 volatile 全局×2，全真实）、A_main.c=3（TIM3 ISR 访 HuXi/PanDuan/Wait，真实）；B 版 18 文件全 PASS——其中 RxData_* 隐患因变量定义在 Variable.c（extern）而单文件分析不可见，属工具边界非误判。**"ISR 只置标志"整改后，共享变量是否 volatile 的检查难点从 ISR 文件转移到了变量定义文件**。

## 10. 生成检查单（桌面宠物/四足机器人场景）

1. 舵机数量>定时器通道时：列资源表（TIM2×4+TIM3×1=5 路 50Hz 是 C8T6 上限方案），必要时软件 PWM 或串行总线舵机。
2. 对称安装的舵机要镜像换算（(180-Angle)），左右腿同一"语义角度"接口。
3. 动作函数必须可打断：每个延时点后查模式标志；打断粒度=最小延时。
4. 遥控命令表只写一份（函数参数区分来源），每个 case 有 break——贯穿=复合故障。
5. ISR 里只允许置变量/标志，刷屏、DMA 启停、长计算一律主循环。
6. 多串口外接模块（语音/蓝牙）注意模块波特率差异，同款不同批次都可能不同（作者 txt 实证）。
7. 电量检测给充电状态留阈值区间（充电电压>满电电压），百分数映射覆盖完整量程。
