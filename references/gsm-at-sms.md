# GSM 模块 AT 指令短信报警（SIM800C / SIM900A，实测基准：火灾远程报警工程）

> 实测来源：F103C8 SPL 工程「基于 GSM 模块的火灾远程报警系统」——DS18B20 温度 + ADC0/ADC1 烟雾/火焰 + OLED + 蜂鸣器，报警时经 USART1(9600) 向 GSM 模块发 AT 短信。本文是生成 GSM 短信代码的完整知识基准。

## 1. 硬件连接

| STM32 | GSM 模块 | 说明 |
|---|---|---|
| PA9 (USART1_TX) | RXD | 交叉连接 |
| PA10 (USART1_RX) | TXD | 交叉连接 |
| GND | GND | **必须共地** |
| — | VCC 3.7~4.2V | **独立供电 ≥2A 峰值**，勿用开发板 USB 5V/1A |

**供电是第一大坑**：SIM800 射频发射瞬间电流可达 2A，电源带不动会导致模块莫名重启/注册不上网/短信发一半断。现象：AT 能通但 `AT+CSQ` 后死机或 `AT+CMGS` 无响应 → 先查供电（加 470µF+100nF 就近电容）。

波特率：模块默认多数为 115200，工程实测用 9600（`AT+IPR=9600` 可设）。9600 更稳（杜邦线/光耦隔离场景），发送 1 字节 ≈1ms，一条短信 AT 序列约 1~2s，可接受。

## 2. 上电自检序列（建议每次开机执行，带超时回读）

```
AT                      → OK                    （链路通）
ATE0                    → OK                    （关回显，简化解析）
AT+CPIN?                → +CPIN: READY          （SIM 卡就绪；否则查卡/锁 PIN）
AT+CSQ                  → +CSQ: <rssi>,0        （信号 0-31，≥10 才可靠发送）
AT+CREG?                → +CREG: 0,1            （0,1=已注册本地网；0,2=搜索中，等 10~60s 重查）
```

**模块冷启动到注网需 2~10 秒甚至更久**。上电立刻报警的场景：先把自检做成状态机，注网成功前置 `gsm_ready=0`，报警发送前检查——未就绪时先本地响蜂鸣器，就绪后补发。

## 3. 发送文本短信（Text 模式，工程实测序列）

```
AT+CSCS="GSM"                 → OK     字符集 GSM 默认（纯英文）
AT+CMGF=1                     → OK     文本模式
AT+CMGS="+8617341163836"      → >      等回 '>' 提示符（不是 OK！）
dangerous!                    （正文）
0x1A                          （Ctrl+Z 结束符，无 \r\n 跟在正文后）
                              → +CMGS: <nr>  然后隔 1~10s → OK（发送成功）
AT&F                          → OK     工程收尾发恢复出厂（可选；会清所有自定义配置）
```

要点：
- **`AT+CMGS` 的应答是 `>` 提示符**，正文打完后发单字节 `0x1A` 结束。0x1A 之后不要再发任何字符，等 `+CMGS`。
- **超时**：`>` 等 2s、`+CMGS/OK` 等 30~60s（注网慢时很长），超时按失败处理。
- 中文短信：`AT+CSCS="UCS2"` + `AT+CSMP=17,167,0,8`，正文按 UCS2 十六进制编码发——复杂度高，报警类场景建议纯英文/拼音正文（`dangerous!`、`FIRE ALARM Temp=45`）。
- 号码**必须用宏/配置区集中**，禁止散在业务代码里：`#define GSM_SMS_TARGET "+8617341163836"`。

## 4. 铁律：每条 AT 后必须回读，禁止盲等

反面案例（实测工程写法，能跑但不可靠）：
```c
Serial_Printf("AT+CMGF=1\r\n");
Delay_ms(500);                  // 盲等：模块忙/掉线/波特率错都发现不了
```
正确范式（复用 RXNE 中断 + 行缓冲，expect 带超时）：
```c
/* Serial 层已有 RXNE 中断收字节入环形缓冲；加： */
uint8_t GSM_WaitFor(const char *expect, uint32_t timeout_ms) {
    uint32_t t = 0;
    while (t < timeout_ms) {
        if (gsm_line_contains(expect)) return 1;   /* 在收到的行里找 "OK"/">"/"+CMGS:" */
        Delay_ms(10); t += 10;
    }
    return 0;
}
/* 发送： */
GSM_SendCmd("AT+CMGF=1\r\n");
if (!GSM_WaitFor("OK", 2000)) gsm_error_handler();  /* 失败：重试/降级/置错误标志 */
```
失败策略建议：整体序列最多重试 2 次；仍失败置 `gsm_fail=1` 让本地报警持续（**短信只是通知手段，本地声光报警才是保底，不能因 GSM 挂了连蜂鸣器都不响**）。

## 5. 报警节流三件套（避免短信轰炸 & 漏报）

| 机制 | 实现 | 防什么 |
|---|---|---|
| **锁存** | 报警条件成立置 `alarm_latched=1`，只发一条；恢复后清零 | 报警持续期间每 10ms 重发一条的轰炸（反面：无节流时 1 小时发 360 条） |
| **冷却** | 恢复后须稳定 `COOLDOWN_S` 秒才允许再次触发 | 传感器在阈值附近抖动导致反复发 |
| **重发升级** | 报警持续超 `RESEND_MIN` 分钟且未恢复 → 再发一条「仍报警」 | 长时间火灾只收到一条短信的问题（锁存的副作用） |

实测工程用 `state + count` 实现了最简锁存（报警置 state=1 且 count==0 才发，恢复清零）——锁存对了，但**没有重发升级，也没有 GSM 未就绪时的补发**，属可接受但应向用户说明的简化。

## 6. 阈值判断方向（对照传感器极性，两处实测教训）

- 换算方向决定比较方向：`raw*100/4096`（正向，值大=浓度高）→ `val > YZ` 报警；`100 - raw*100/4096`（反向，值大=浓度**低**）→ 应 `val < YZ` 报警。**同一工程里混用两种换算却沿用同一方向的比较，是最隐蔽的逻辑翻转**（实测工程 AD1 正向 `>`、AD2 反向后仍 `>`，火焰通道方向存疑）。
- 上电先串口打印各通道原始值与换算值，用打火机（火焰）/酒精棉（烟雾）人工标定阈值再写死；`uint8_t` 存温度会丢负温与小数（DS18B20 返回值建议 `int16_t` 或 ×10 定点 `uint16_t`）。

## 7. 生成代码检查单（GSM 报警类工程）

1. USART 波特率与模块一致（9600/115200），TX/RX 交叉、共地
2. 上电自检序列带超时回读，注网未就绪不硬发
3. `AT+CMGS` 等 `>`、正文后单发 `0x1A`、等 `+CMGS`（30~60s 超时）
4. 号码/阈值全部宏集中定义
5. 锁存+冷却+重发升级三件套齐备
6. GSM 失败不影响本地声光报警（通知可丢、报警不可丢）
7. 短信正文纯英文（避开 UCS2 编码复杂度），含关键数值（温度/通道）
8. RXNE 中断收缓冲必须 volatile + 行解析（validator 必查）
9. 供电独立 2A，`AT+CSQ`<10 先解决信号再谈发送
